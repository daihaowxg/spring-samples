# 示例代码与日志规范

本规则适用于所有演示示例代码，确保代码具有良好的可读性、可运行性和教学价值。

---

## 🎯 1. 适用范围

- `src/main/java/**/sample*/**/*.java`
- `src/main/java/**/demo/**/*.java`
- 其他用于演示教学目的的 Java 源文件

---

## 📦 2. 包结构规范 (Package Structure)

### 2.1 `package-info.java` 要求

**每个包路径下必须包含一个 `package-info.java` 文件**，用于说明该包的职责与内容。

- **职责说明**：简要描述该包下类的共同主题或功能定位
- **类清单**：使用 `<ul>` 列出包内的主要类，并用 `{@link}` 链接
- **学习指引**：说明该包在整体学习路径中的位置或前置知识

**示例格式：**

```java
/**
 * [阶段/主题描述]
 * <p>
 * 本包包含以下示例类：
 * <ul>
 * <li>{@link ClassName1} - 简要说明</li>
 * <li>{@link ClassName2} - 简要说明</li>
 * </ul>
 * <p>
 * [学习建议或前置知识说明]
 */
package your.package.name;
```

---

## 🧪 3. 示例代码编写 (Sample Code)

- **自说明性**：每个示例类的类头必须包含详细的 Javadoc，并使用 `{@link ...}` 链接到对应的核心类。
- **无状态设计**：示例代码应尽量编写为可直接运行的 `main` 方法，且不应产生持久化的副作用。

---

## 📝 4. 日志与反馈

- **SLF4J 优先**：禁止使用 `System.out.println`（除非是纯粹的控制台演示示例），应优先使用 SLF4J 记录日志。
- **中文控制台输出**：对于面向教学的演示输出，控制台提示信息应使用中文。
