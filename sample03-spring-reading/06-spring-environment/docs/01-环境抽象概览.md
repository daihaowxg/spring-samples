# Spring Environment 抽象概览

`Environment` 是 Spring 中用于管理“应用环境”的核心抽象。它主要解决了两个核心问题：**Profiles**（环境隔离）和 **Properties**（属性查找）。

## 1. 核心体系结构

Environment 的设计遵循了高度的接口分离和职责继承原则：

- **`PropertyResolver`**: 定义了最基础的属性访问和占位符解析（`${...}`）能力。
- **`Environment`**: 继承自 `PropertyResolver`，增加了对 **Profiles** 的支持。
- **`ConfigurableEnvironment`**: 允许在运行时配置属性源（PropertySources）和激活特定的 Profiles。

## 2. 核心组件说明

### 2.1 PropertySource (属性源)
`PropertySource` 是对任何 key-value 对来源的抽象。Spring 允许我们将多种来源组合在一起。

- **`MutablePropertySources`**: 内部持有一个属性源列表，支持**优先级排序**。查找属性时，会按顺序遍历，先找到的胜出。

### 2.2 PropertyResolver (属性解析器)
负责将原始字符串解析为最终值。
- 支持类型转换（与 Spring ConversionService 集成）。
- 支持递归解析占位符，如 `app.url=http://${host}:${port}`。

### 2.3 Profiles (环境剖面)
允许我们将配置逻辑分组。常见的场景包括：
- `dev`: 开发环境，使用 H2 内存数据库。
- `test`: 测试环境。
- `prod`: 生产环境，使用 MySQL。

## 3. 标准环境 (StandardEnvironment)

在普通的 Java 应用中，Spring 默认提供 `StandardEnvironment`，它自动预置了两个高优先级属性源：
1. **`systemProperties`**: JVM 系统属性（`System.getProperties()`）。
2. **`systemEnvironment`**: 操作系统环境变量（`System.getenv()`）。
